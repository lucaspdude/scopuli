# scopuli — context glossary

> Domain terms and resolved decisions for the scopuli project. Updated inline as decisions are made during planning. Lives at the repo root so the implementation reads it first.

## Operator

The single human who runs the vault. They own the master password and the operator token. They create secrets, issue agent keys, read the audit log, and revoke keys. There is **no multi-user role hierarchy** in V0 — every other participant is an "agent" (programmatic access).

## Operator token

A long random `bearer` token (32 bytes, base64url) generated by the server on **first boot**, stored only as `SHA-256(operator_token)` in the database. Printed to the operator's stdout exactly once. The CLI uses it to authenticate every request to the server (`X-Scopuli-Operator` header). It is the same shape as an agent API key, but with the special privileges of the operator.

If the operator token is lost, the operator can reset it via `docker exec -it <container> scopuli rotate-operator-token` after entering the master password.

## Description

A free-form **Markdown** text field attached to a key or secret. Its purpose is to give context to humans and agents reading the resource — not to enforce structure. Typical contents: a one-line summary, usage examples, warnings, links to internal docs. Capped at 8 KB. Stored in the same row as the resource. For secrets, the description is included in the AAD for AES-256-GCM (so any tampering fails decryption). An agent reading a secret also gets the description (unless the requester is restricted).

## Tags

A **CSV list of short labels** attached to a key or secret. Examples: `aws,prod,deprecated`, `temp,oncall`. Lower-case, hyphen-friendly. Max 20 tags per resource, 64 chars per tag. Indexed via `LIKE` prefix matching for filter queries (`scopuli secrets list --tag aws`). Tags are presentational — they do not affect scope or permissions.

## Metadata

A **JSON object of structured key-value pairs** attached to a key or secret. Use when you have well-known fields that should be queryable as actual data: `{"owner_email": "alice@example.com", "cost_center": "eng-42", "rotated_at": "2025-08-01"}`. Max 32 pairs; key 64 chars, value 256 chars. Validated against a schema on every write (must be `object` of strings). Also indexed into FTS5 (flattened as `k1=v1; k2=v2`) for search.

## AAD (additional authenticated data)

The bytes bound to a secret's ciphertext to detect tampering. For V0 secrets, `aad = SHA-256(path || description || uint64_be(version))`. Including `description` in the AAD means a description edit invalidates the old ciphertext — the server must re-encrypt on every description change.

## Annotate

The verb for editing metadata on a resource. Operator or `manage`-permission key holder can annotate a secret or key with new tags / description / metadata. Every annotate call emits an `audit` row. The CLI surface: `scopuli secret annotate <path> --add-tag aws --description "..."` and `scopuli keys annotate <name> --add-tag prod`.

## pi extension

A TypeScript package (`@scopuli/pi-extension`) that plugs into the [pi-coding-agent](https://github.com/lucaspdude/pi-coding-agent) harness. V0 of the extension provides a status bar item showing the connection state to the vault (`🔒 scopuli: up · 4 keys · scope read`). Future versions (v0.1+) add slash commands and tools for the agent. See [`docs/PI-EXTENSION.md`](./docs/PI-EXTENSION.md).

## Master password

The `MASTER_PASSWORD` env var passed to the Docker container. Used **only** at boot to derive the KEK (Argon2id). Never sent over the wire. The operator never types it into the CLI. The only way to access it is via the container's environment — which is the threat boundary we already trust.

## Agent key

A scoped, revocable API key issued by the operator for an agent (LLM runtime, cron job, etc.). Same hash-only-at-rest design as the operator token, but with a `scope` (slash-path globs) and `permissions` (`read` or `manage`).

## Secret

A single `(path, value)` pair. The path is a slash-delimited string (`aws/dev/stripe_key`). The value is encrypted at rest with AES-256-GCM keyed off the KEK, with the path as AAD. A key may only read secrets whose path matches its scope.

## Agent

Any long-running autonomous process that programmatically pulls secrets. Examples: Claude Code, Cursor, OpenHands, custom cron jobs, home automation. Identified to the vault by an agent key. Agents run on the operator's Mac, on other LXCs, on remote hosts — anywhere reachable to the vault over the network.

## LXC

The deployment surface. The vault runs as a Docker container inside a Proxmox LXC, exposed to the LAN (and potentially the public internet) via a reverse proxy (Caddy / Nginx) that terminates TLS. The trust boundary is "anyone who can route to the port" — same posture whether LAN or public.

## V0 deployment posture

The vault is **safe to expose to any network** from day one. The auth model is operator-token-based; the master password never leaves the container. TLS termination is the operator's responsibility (documented but not built into the Go server). The threat model is the same whether the port is reachable from the LAN or the public internet.

## Web UI

The htmx operator console served at `/ui/`, embedded in the binary (templates + Tailwind CSS + vendored htmx, no extra services). The operator logs in with the **master key** (the operator token, exactly the credential the CLI uses). The server verifies it the same way as `X-Scopuli-Operator` and issues a 30-day HttpOnly session cookie, HMAC-SHA-256-signed with a key derived from the KEK (`UISessionKey`) — so sessions survive restarts and are invalidated automatically by `rotate-operator-token` (which re-derives the KEK). The master password itself never crosses the wire. The UI covers: dashboard, secrets (list/search/reveal/create/edit/delete), keys (issue/revoke/edit), and the audit log (hash-chain verification, filters, cursor pagination). Reveals and mutations are audited exactly like their API counterparts. Every UI mutation additionally requires the htmx `HX-Request` header (defense in depth on top of SameSite=Lax cookies). Styling is Tailwind v4 with shadcn/ui design tokens; regenerate `internal/api/assets/app.css` via `make css` (committed, so `go build` needs no Node).

## Out-of-scope resolution rules

These are terms that are explicitly NOT defined in V0. They will land in V1+:
- Multiple operators
- Multi-host / remote MCP (Streamable HTTP) — V0 uses stdio MCP, with the CLI binary local to each host
- Secret versioning / rollback
- Replication / HA
- Secret rotation policies
- OAuth / OIDC / SSO
- 2FA
- HSM / KMS / Shamir shards
- Webhooks for revocation events
